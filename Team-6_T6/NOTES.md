## 1. Status Map

| Endpoint | Success Status | Failure Statuses & Rationale |
| :--- | :--- | :--- |
| **`POST /posts`** | `201 Created` | **400 Bad Request:** Malformed JSON payload. <br> **422 Unprocessable Entity:** Validation failed or media unavailable. <br> **429 Too Many Requests:** Rate limit exceeded. |
| **`GET /posts`** | `200 OK` | **400 Bad Request:** Invalid pagination or sorting parameters. <br> **406 Not Acceptable:** Unsupported `Accept` header. <br> **429 Too Many Requests:** Rate limit exceeded. |
| **`GET /posts/{id}`** | `200 OK` | **404 Not Found:** Post ID does not exist. <br> **406 Not Acceptable:** Unsupported media type requested. |
| **`PATCH /posts/{id}`** | `200 OK` | **404 Not Found:** Post ID does not exist. <br> **412 Precondition Failed:** ETag mismatch via `If-Match`. <br> **422 Unprocessable Entity:** Field validation failed. |
| **`DELETE /posts/{id}`** | `204 No Content` | **404 Not Found:** Post ID does not exist. |
| **`POST /posts/{id}/archive`** | `200 OK` | **404 Not Found:** Post ID does not exist. <br> **409 Conflict:** Post is already archived. |

## 2. Type Catalogue

| Stable Type URI | Triggering Condition |
| :--- | :--- |
| `https://namogram.com/errors/validation-error` | Triggered when the request body fails field validation checks, such as a missing mandatory field or malformed URL. |
| `https://namogram.com/errors/media-unavailable` | Triggered when the upstream storage client fails to verify or fetch the provided `mediaUrl`. |
| `https://namogram.com/errors/post-not-found` | Triggered when querying, updating, or deleting a resource ID that does not exist in the store. |
| `https://namogram.com/errors/illegal-transition` | Triggered when an invalid state transition is attempted, such as archiving an already archived post. |
| `https://namogram.com/errors/precondition-failed` | Triggered when the `If-Match` header does not match the current resource ETag. |
| `https://namogram.com/errors/rate-limit-exceeded` | Triggered when the client exceeds the allowed request rate within a time window. |
| `https://namogram.com/errors/not-acceptable` | Triggered when the client requests a format in the `Accept` header that the service cannot produce. |

## 3. Labeled Problem Details Body

Below is an example of an RFC 7807 Problem Details response body:

```json
{
  "type": "https://namogram.com/errors/validation-error",
  "title": "Validation Failed",
  "status": 422,
  "detail": "The request body failed schema validation."
}
```

- **[1] `type`:** Stable URI identifying the error category.
- **[2] `title`:** Short, human-readable summary of the problem type.
- **[3] `status`:** HTTP status code generated by the origin server.
- **[4] `detail`:** Explanation specific to this occurrence of the problem.

## 4. Field-Level 422 Validation Reporting — Two Bad Fields

When a request body contains multiple invalid fields, the service validates all fields before executing business logic and collects the failures into a single `422 Unprocessable Entity` response.

```json
{
  "type": "https://namogram.com/errors/validation-error",
  "title": "Validation Failed",
  "status": 422,
  "detail": "The request body failed schema validation with 2 errors.",
  "errors": [
    {
      "field": "caption",
      "reason": "Caption cannot be empty or blank."
    },
    {
      "field": "mediaUrl",
      "reason": "Media URL must be a valid HTTP/HTTPS URL."
    }
  ]
}
```

## 5. Safe Retries & Signaling Status Codes

### Retryable Endpoints

- `GET /posts` and `GET /posts/{id}` — Naturally safe and idempotent read operations.
- `POST /posts` — Safe to retry only when carrying an `Idempotency-Key` header.

### Non-Retryable Endpoints

- `POST /posts` without an `Idempotency-Key` — May create duplicate post entities.
- Any `4xx` client error, such as `422`, `400`, or `404` — Retrying an unchanged request generally produces the same failure.

### Status Codes Signaling Client-Safe Retries

- **`429 Too Many Requests`:** Indicates that the client has exceeded its rate limit. Retry after the duration specified in the `Retry-After` header.
- **`503 Service Unavailable`:** Indicates temporary server overload or dependency downtime. Retry after the duration specified in the `Retry-After` header.

## 6. Mapping Internal Errors to Clean Client Errors

### Mapping Location

Handled centrally inside:

- `middleware/problemDetails.js`
- `utils/mediaClient.js`

### Scenario

When the upstream database or media server throws a raw connection exception, such as `ECONNREFUSED`, the internal error handler catches the exception, logs the full technical details server-side, and returns a clean, sanitized error payload to the caller.

Example response:

```json
{
  "type": "https://namogram.com/errors/media-unavailable",
  "title": "Media Service Temporarily Unavailable",
  "status": 503,
  "detail": "The media verification service is temporarily unreachable. Please try again later."
}
```

### Details Hidden from the Caller

The following internal details are masked:

- Stack traces
- Internal server file paths
- Database cluster IP addresses
- Database engine query syntax error messages
- Internal microservice infrastructure credentials

## 7. Dual Representation: JSON vs XML Content Negotiation

The service supports content negotiation through the `Accept` header. The same post entity can be represented in JSON or XML format.

### JSON Representation

**Request header:** `Accept: application/json`

```json
{
  "id": "post_a06_demo",
  "authorId": "usr_anon",
  "caption": "Namogram Assignment 06 Post",
  "mediaUrl": "https://cdn.namogram.com/a06_photo.jpg",
  "likesCount": 0
}
```

### XML Representation

**Request header:** `Accept: application/xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<post>
  <id>post_a06_demo</id>
  <authorId>usr_anon</authorId>
  <caption>Namogram Assignment 06 Post</caption>
  <mediaUrl>https://cdn.namogram.com/a06_photo.jpg</mediaUrl>
  <likesCount>0</likesCount>
</post>
```
